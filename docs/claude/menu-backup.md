# Меню, «Настройки» и резервная копия

> Перенесено из `CLAUDE.md`. Читать при работе с меню в шапке, экраном «Настройки», `buildBackup` / `parseBackup` / `mergeBackup`, напоминанием о копии.

- **Меню и экран «Настройки».** В шапке справа кнопка меню (три полоски, 44x44), она открывает
  боковую панель с пунктами «Мой план» и «Настройки». Пункты - данные (`menuItems`: `id`,
  `screen`, `title`, `sub`), а что открыть, решает `App`: `onSelect` ставит
  `planScreen = item.screen` (`"list"` или `"settings"`). «Мой план» - про тренировки
  (расписание, программы, свои тренировки), «Настройки» - один блок `settingsSections`
  (вес гантелей, тема, экран, резервная копия). Компоненты (`MenuButton`, `MenuDrawer`)
  стоят **после** `App` в конце файла: код до `App` тесты исполняют как обычный JS, а JSX
  Node не разберёт. Цвета в меню - только токены. Подпись «ТЕСТОВАЯ ВЕРСИЯ» внизу панели
  есть только в beta (`APP_VARIANT`). Экран настроек напрямую никто не открывает
  (`setPlanScreen("settings")` в коде нет). В тестовой версии значок BETA стоит на строке подписи («PUSH / PULL /
  LEGS»), а не рядом с названием: рядом он ломал шапку на две строки.
- **Резервная копия (меню -> «Настройки»).** `buildBackup` / `parseBackup` /
  `mergeBackup` стоят вне `App` и тестируются исполнением. Сохранение идёт через
  `navigator.share` с файлом (в iOS-PWA blob-скачивание ненадёжно), запасной
  путь - ссылка `download`. Загрузка **только добавляет**: журнал по `ts`
  (локальная запись побеждает при равном `ts`), сессии и прочее по ключу;
  `schedule` и `dbMode` берутся из файла лишь на устройстве без истории. Корзина
  и `resuming` в импорт не попадают. `data.lastBackup` - дата последней копии.
  Напоминание (`backupDue`): баннер на главном экране, если в журнале >= 3 записей
  и копия старше 14 дней или её не было; «ПОЗЖЕ» откладывает на 3 дня
  (`data.backupSnooze`). Пока в тренировке есть хоть один закрытый подход, баннер скрыт.
