# Данные: контракт и localStorage

> Перенесено из `CLAUDE.md`. Читать при работе с `WARMUP` / `ALTERNATIVES` / `PROGRAM`, полями данных, `loadData` / `saveData` / `pruneOldKeys`.

## Контракт данных

Упражнение в пуле: `{ id, name, sets, reps, rest, steps, danger, warn }` —
все поля обязательны для всех 210 упражнений.

Разминка каждого дня обязана давать `label, sub, duration, why, avoid,
blocks[{ title, time, items[{ name, sets, tip, steps }] }]`.

Секция 19 **выводит список обязательных полей из самого рендера** — сканирует
обращения `wu.*`, `block.*`, `item.*`, `ex.*` в JSX. То есть добавил поле в
UI — оно автоматически стало обязательным во всех вариантах данных. Это
единственный паттерн, который реально остановил серию падений вида
`wu.avoid.map is not a function`. Не ломай его: не хардкодь список полей
обратно в тест.

## localStorage

Ключ `ppl_tracker_v4`:

| поле | что |
|---|---|
| `sessions` | незавершённая текущая работа, ключ `YYYY-MM-DD_день` |
| `history` | завершённые тренировки с `detail` |
| `swaps` | замены упражнений, **scoped по сессии** |
| `skipped` | пропуски, **scoped по сессии** |
| `customWorkouts` | свои дни из конструктора |
| `customSets` | изменённое количество подходов |
| `addedEx` | упражнения, добавленные на ходу |
| `resuming` | какая запись истории сейчас редактируется |
| `schedule` | массив из 7 элементов: ключ дня или `null` |
| `dbMode` | `"single"` / `"pair"` — вес за одну гантель или за пару |
| `trash` | удалённые записи для восстановления |

Таймер отдыха — отдельный ключ `sila_timer`.

Даты в ключах чистятся `pruneOldKeys` через 400 дней, история режется до
`HISTORY_LIMIT`. При восстановлении из корзины срез `HISTORY_LIMIT + 1`, иначе
восстановленная запись сразу отваливается.
