# Workout Routine — PWA трекер тренировок

Личное приложение для зала. Один пользователь (iPhone 11 Pro Max, Safari,
установлено на домашний экран). Интерфейс на русском. Хостинг — GitHub Pages:
`https://shattersxd.github.io/workout`.

Комментарии в коде пишутся по-русски, как в существующем коде.

Здесь только то, что нужно в каждой сессии. Подробности по частям приложения —
в `docs/claude/` (таблица «Справка» в конце): нужный файл читать **до** правки этой части.

---

## Как собирается проект

Нет бандлера и нет шага сборки в рантайме. Приложение — **один HTML-файл**,
который в браузере компилирует себя сам через Babel standalone.

```
src/shell/head.html          <- <head>, CSS, лоадер, манифест, иконки, бутстрап Babel
src/workout_tracker.jsx      <- ВСЁ приложение: данные + компонент App
src/shell/tail.html          <- ErrorBoundary, ReactDOM.createRoot, </html>
src/beta/*.jsx               <- только для тестовой версии (beta/)
        |
        v  python3 scripts/build.py
index.html                   <- то, что отдаётся GitHub Pages
beta/index.html, beta/sw.js  <- тестовая версия

vendor/                      <- React 18.3.1, ReactDOM 18.3.1, Babel 7.23.10 (не с CDN)
sw.js                        <- настоящий service worker, регистрируется из index.html
```

**Внешних зависимостей при запуске нет.** Библиотеки лежат в `vendor/`
(версии и SHA-256 - в `vendor/README.md`, тесты сверяют суммы) и кэшируются
`sw.js`, так что приложение стартует и без интернета. Файлы в `vendor/` не
править; `.gitattributes` запрещает git менять в них переводы строк. Обновили
библиотеку - поднимите `CACHE` в `sw.js` (`sila-v7`...), иначе телефон останется
на старой копии.

`build.py` только склеивает файлы и убирает границу ES-модуля (подстановки через
`replace_once`, падают, если не сработали):

| в `src`                                     | в `index.html`                        |
|---------------------------------------------|---------------------------------------|
| `import { useState, ... } from "react";`     | `const { useState, ... } = React;`    |
| `export default function App() {`            | `function App() {`                    |

Больше ничего не трансформируется. Поэтому **всё, что попадает в `src`, должно
быть валидным для Babel 7.23 на iOS как есть** — см. «Запреты».

## Рабочий цикл и деплой

```bash
python3 scripts/build.py && node tests/test_pwa.js   # должно быть 374/374
python3 scripts/build.py --check                     # index.html не отстал от src/
```

Правим **только `src/`**. `index.html` — артефакт сборки; редактировать его
руками нельзя, следующая сборка затрёт правку. Коммитить `index.html` нужно,
потому что GitHub Pages отдаёт именно его.

Перед деплоем должно быть **374/374 PASSED**. Красный тест — это не повод
править тест, это повод править код (исключения — ниже).

Деплой: `git add -A && git commit -m "..." && git push`. GitHub Pages репозитория
`shattersxd/workout` раздаёт `index.html` из ветки `main`, корень репозитория
(вместе с `vendor/` и `sw.js`), публикация — полминуты-минуту. Других хостингов нет.
На телефоне новая версия приходит при ближайшем открытии, когда есть сеть.

## Запреты (каждый — это упавшее на iPhone приложение)

Почему так и примеры падений — `docs/claude/platform.md`.

1. **Не-ASCII символы внутри строковых литералов JS.** Babel 7.23 в Safari на iOS
   на них падает. Можно только **кириллицу** (U+0400–U+04FF), **градус** `°` (U+00B0)
   и **эмодзи** (U+1F000+). Запрещены в том числе: `× · → ← № ✓ ✗ ✎ − – — ⚠ ⇄ ▾ ▴ ▲ ▼ ─ … « » “ ” ’`.
   Замены: `x` вместо `×`, `->` вместо `→`, `-` вместо `−/–/—`, эмодзи вместо `✓ ⚠ ✎`.
   В **комментариях** можно всё. Секции 1 и 9.
2. **Новый синтаксис.** Пресет только `react`, ничего не транспилируется. Нельзя:
   `?.`, `??`, `||=`, `&&=`, `??=`, `Array.prototype.at`, `structuredClone`,
   `Object.hasOwn`, `1_000`. Вместо `a?.b` писать `a && a.b`. Секция 2.
3. **Пропущенные запятые в объектных литералах.** Node прощает, Babel на iOS — нет.
   Секция 16 проверяет на любой глубине.
4. **Структура больших литералов.** Ключ, оказавшийся после закрывающей `};` объекта,
   и дубли ключей Node принимает, Babel — нет. Секция 11.
5. **Вёрстка iOS:**
   - на `body` нет `overflow-x: hidden` (ломает `position: sticky`), вместо него `max-width: 100vw`;
   - `input, button, select { font-size: 16px }` глобально (меньше — автозум);
   - цель нажатия не меньше **44pt** (секция 17);
   - `env(safe-area-inset-*)` работает только с `viewport-fit=cover`;
   - `apple-touch-icon` — только **PNG в base64** (SVG на iOS не работает);
   - таймер — на абсолютном времени (`endsAtRef` + `endsAt`), не на счётчике тиков.
6. **Компилировать только после разбора страницы.** Чтение `#app-src` и
   `Babel.transform` идут внутри `onDocumentParsed(...)` в `head.html`. Не убирать:
   тест проверяет.

## Как устроен `src/workout_tracker.jsx`

~4470 строк, один файл, порядок сверху вниз:

| | что |
|---|---|
| `WARMUP` | разминки по ключу дня. Ключи **обязаны совпадать** с ключами `PROGRAM` |
| `ALTERNATIVES` | ~60 групп замен: `exId -> [варианты]`. Пул ~210 упражнений |
| `PROGRAM` | пресеты: `push`, `pull`, `legs`, `fullbody_a`, `fullbody_b`, `fullbody_c` |
| `ACHIEVEMENTS` | 37 ачивок в разделах `ACH_GROUPS`; условия считает `achStats` |
| `WEEK_SCHEDULE` | дни недели |
| константы | `STORAGE_KEY = "ppl_tracker_v4"`, `HISTORY_LIMIT = 200`, `SESSION_KEEP_DAYS = 400` |
| `pruneOldKeys` / `loadData` / `saveData` | персистентность |
| чистые функции | тема, резервная копия, фильтр журнала, подсчёт ачивок |
| `App()` | весь UI и вся логика, ~2800 строк |
| после `App` | компоненты с JSX: меню, праздник ачивок |

Код до `App` тесты исполняют как обычный JS, поэтому **компоненты с JSX ставятся
после `App`**: Node их не разберёт.

**Данные.** Основной ключ `ppl_tracker_v4`, таймер — `sila_timer`. Весь `data` уходит
в файл резервной копии, поэтому настройки устройства и токены лежат **отдельными
ключами** (`sila_theme`, `ppl_spotify_beta`, `sila_sound_beta`). Упражнение в пуле:
`{ id, name, sets, reps, rest, steps, danger, warn }`, все поля обязательны. Секция 19
**выводит обязательные поля из самого рендера** — не хардкодить список полей в тест.

## Поведение, которое легко сломать

Подробности — `docs/claude/workout-logic.md`.

- Тренировку нельзя завершить пустой: нужно не меньше 3 упражнений, упражнение
  выполнено, только когда отмечены **все** его подходы.
- Подход нельзя закрыть без веса. Вес отмеченного подхода менять нельзя (`readOnly`,
  `updateSet` не принимает `weight` при `done: true`).
- Запись `src: "manual"` всегда «ЗАВЕРШЕНА»; «НЕ ЗАКОНЧЕНО» — только у автосохранений ниже 100%.
- Каждый закрытый подход перезапускает отдых; зависимости `useEffect` таймера обязаны
  включать `timer.endsAt`. **Известная неисправность (не исправлена):** отдых не
  восстанавливается после выгрузки приложения системой.
- Возобновление обновляет ту же запись (сессия восстанавливается из `entry.detail`);
  отмена редактирования запись не удаляет.
- Прошлые веса читаются из журнала (`getPastExSets`), а не только из `sessions`:
  `finishWorkout` удаляет сессию после сохранения.
- Прогрессия сортируется по строке ISO-даты, не по `ts`.
- Даты — по местному времени: `todayKey()` без `toISOString()`.
- `dbMode` фиксируется в записи и не применяется к истории задним числом.
- Загрузка резервной копии **только добавляет** (`mergeBackup`), ничего не затирает.
- Ачивки: новая — с новым `id`; `ACH_LEGACY` и их условия не менять.
- Каждый движущийся элемент помечен `app-anim`; без анимации всё должно читаться.

## Тестовая версия (`beta/`)

`https://shattersxd.github.io/workout/beta/` = тот же код + `src/beta/*.jsx`, вставленные
перед `App` (в боевом `index.html` их нет). Жёсткие правила:

- **Изоляция:** у страниц на `github.io` общие `localStorage` и Cache Storage. Бета пишет
  только в свои ключи (`ppl_tracker_beta`, `sila_timer_beta`) и кэш `sila-beta-*`;
  боевой ключ только **читает** (`PROD_STORAGE_KEY`).
- Швы в боевом коде минимальны и защищены `typeof X === "function"`.
- Запреты выше действуют и для `src/beta/`.
- Соц-модули (`social.jsx`, `compete.jsx`) не делают сетевых вызовов. Профиль, вес тела,
  самочувствие, травмы и журнал не попадают в соц-пакет ни при каких настройках;
  в комнату уходят только счётчики, веса — никогда.
- Боты всегда помечены 🤖 и строкой «В комнате: N человек и M бота-партнёра»;
  переключателя, скрывающего пометку, нет и быть не должно.
- Тон: бета на «вы», основная версия на «ты» (решение заказчика).
- Бета всегда тёмная (панели на hex). Не обещать звук и музыку при свёрнутом приложении.

## Тема оформления

Подробности — `docs/claude/theme.md`.

- Цвета в стилях — только токены (`var(--bg-0c0c0f)`), голые серые hex запрещены
  (секция 24). Новый токен добавляется в **обе** темы в `head.html`.
- Цвета дней как текст и обводка — через `ink()`; фон и подкраска — без `ink`.
- Скрипт темы в `<head>` и `themeResolve` в приложении обязаны совпадать.

## Тесты

`tests/test_pwa.js` — свой харнесс, 27 секций, 374 теста. Новую секцию добавлять
**перед** блоком `SUMMARY` и `process.exit()`, иначе она не запустится. Асинхронные
тесты — через `testAsync` (`test` не ждёт промисы). Список секций — `docs/claude/tests.md`.
